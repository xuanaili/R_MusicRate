# ai/planning/ — 版本规划目录使用说明

`ai/planning/` 存放本项目的**版本规划文档**（进行中 / 已定稿 / 已完成的版本设计）。它与 `ai/` 下其余三个归档型子目录性质不同：

- `ai_case_notes/` / `knowledge/` / `skill/` 是**归档型**：事后沉淀，按 `YYYYMMDD_` 命名；
- `ai/planning/` 是**进行中工作文档**：版本演进，按**版本号**命名。

每个子目录（含本目录）都有 `00_template.md`，新增内容时先读模板再按格式写。

## 目录约定

| 文件 | 内容 |
|---|---|
| `00_template.md` | 本模板：新建规划文档前先读 |
| `ROADMAP.md` | （可选）版本路线图：尚未细化的未来版本，一行一个 |
| `BACKLOG.md` | （可选）跨版本待办 / 暂不解决清单 |
| `v0.x_简短英文描述.md` | 单个版本规划（按版本号命名，不按日期） |

## 版本规划文档模板

```markdown
# v0.x — <版本主题>

| 项 | 值 |
|---|---|
| 状态 | 规划中 / 已定稿 / 已完成 |
| 定稿日期 | YYYY-MM-DD |
| 基线版本 | v0.y（承接设计见 `v0.y_*.md` 对应小节，或见 `ai/knowledge/` 基础概念） |

> 分工：`README.md` 只放稳定信息（简介 / 技术栈 / 启动 / 当前状态 / 版本演进索引），
> 单个版本的详细设计一律写在本文件；`CLAUDE.md` 的「文档导航」表负责把 AI 指向
> 当前版本规划与基线文档。
```

## 基线 / 承接规则（防止"只看到一个版本"）

1. 每个新版本规划开头写「基线版本」：用 3~5 行**直接内联**上一版本的关键设计决策（只摘要不复制全文），细节用链接指向上一版本规划文档的锚点；
2. 跨版本稳定的基础概念（数据库模式、认证流程、计算公式等）沉淀到 `ai/knowledge/`，各版本共用，**不**放进单个版本规划；
3. 版本开发完成：规划文档状态标「已完成」保留备查（它是"这段历史为什么这么设计"的记录）；其中仍生效的"已定决策"提升进 `ai/knowledge/`。

## 与 README / CLAUDE.md 的分工

| 文件 | 承载 |
|---|---|
| `README.md` | 稳定信息：项目简介、技术栈、快速开始、目录结构、当前版本状态、版本演进索引（一行一个版本 + 链接） |
| `ai/planning/` | 演进信息：每个版本的详细规划（功能 / 决策 / 架构 / DB / 接口 / 组件 / 路线 / 难点 / 待做） |
| `CLAUDE.md` | 导航：「文档导航」表（当前版本规划 → 基线 → 基础概念），按需 read，不同时灌入全量历史 |
