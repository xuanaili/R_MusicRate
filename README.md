- 公共专辑详情的字删掉

和本地图床一样，上传后的歌曲会有一个URL，数据都会存在MusicRate/backend/data/album_track里面（后续这个上传要做到能处理ncm这种歌曲），URL和整轨的时长都存吧

- 在播放列表中，我只支持整张专辑的播放，也就是说可以把整张专辑当作一首歌来判断，然后最上方的单曲循环，随机播放，顺序播放都改成一个小图标，点击会切换的那种，和现在广大音乐播放器一样，图标就放在清空当前歌单的左边，原先的那三栏现在也变成添加时间，名称排序和评分排序了；。然后支持点击添加和拖拽添加，同理上半部分支持点击删除和拖拽删除，下方只显示专辑名，歌手和评分
- 播放逻辑，退出侧边栏播放当前页面的歌，刚打开此页面也会播放当前页面的歌（方便后续音乐列表选择专辑就跳转的逻辑）

- 首先，我们打开侧边栏后，会开始寻找Album_用户ID表里面所有的专辑序号source_pool_id，然后我们带着source_pool_id再去album_pool表里去查看哪些source_pool_id的专辑的mp3_url非空，然后我们带着符合要求的source_pool_id再去Album_用户ID表里提取出对应的score,album_name,created_at,source_pool_id,singer。
- 我整体的建表逻辑是：新建一个user_playlist的表，里面存上user_id,和一个二维数组【【播放列表名】【【album_id(也就是source_pool_id)数组，用于播放列表】】】,current_album_id(这个是当前播放列表播放到那一首专辑的标识)，和current_playlist_id(这个是当前选择的播放列表是第几个)，然后初始化的时候，这个元素应该是[['默认列表'],[[]], ,0]，每次打开侧边栏，需要读取user_playlist的表，展示播放列表，这也需要一个api接口。
- 新建播放列表的话就相当于[['默认列表','新建播放列表1']，[[],[]], ,1]，这里也需要一个api接口（这里能直接更新了）
- 点击播放列表具体的专辑，会跳转到那个专辑详细页
- 专辑播放完成后会根据专辑列表的播放逻辑，切换到下一个专辑详情页，同时判断和current_album_id是否到达和current_playlist_id播放列表的边界，也就是最后一首

# 文件介绍
- MusicRate/ # 项目根目录
  - frontend/ # 前端（Vue）
    - assets/ # 静态资源（图片/字体/全局CSS）
      - css/
        - global.css # 全局样式（比如重置样式、通用布局）
        - star.css # 评分星星专属样式
      - images/ # 音乐封面/图标等
    - components/ # Vue组件（复用的小模块）
      - MusicItem.vue   # 单首音乐的卡片组件（评分+评论）
      - StarRating.vue  # 评分星星组件（复用）
    - js/         # 辅助JS（请求封装/工具函数）
      - api.js  # 封装后端接口（比如获取音乐、提交评论）
      - utils.js # 工具函数（比如评分计算、时间格式化）
    - index.html  # 入口页面
    - app.js      # Vue入口（挂载实例、路由等）
  - backend/        # 后端（Flask）
    - app.py      # 入口文件（启动服务、注册路由）
    - routes/     # 接口路由拆分（按模块）
      - music.py # 音乐相关接口（获取列表、提交评分/评论）
      - user.py  # 后续加用户登录时用
    - utils/      # 后端工具函数
      - data_handler.py # JSON/数据库读写封装
      - score_calc.py   # 评分计算（比如加权平均分）
    - config.py   # 配置文件（数据库地址、端口、密钥等）
    - data/       # 数据存储（JSON/数据库文件）
      - music_data.json #这个是示例
  - .gitignore      # 忽略不需要提交的文件（venv/、node_modules/等）
  - README.md       # 项目说明（启动步骤、功能清单、待优化项）
