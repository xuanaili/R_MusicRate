## 功能概述

把 MusicRate 从「纯桌面布局」改造为「桌面不回归 + 手机可用」。**本版重点 = 专辑详情页 `AlbumDetail.vue` 及其 6 个子 Tab**（基础信息 / 曲目列表 / 歌词展示 / 听后感 / 平台评论 / AI 助手）；同时给出全站「底色模糊」在 iOS Safari 上的降级方案；其他主页面（首页三 Tab、标签详情、池详情）与侧边栏弹窗列 P1/P2，不阻塞本版发布。

唯一适配目标设备：**iPhone 14 Pro 自带 Safari**（CSS 视口 393×852、DPR 3、灵动岛 + 底部手势条）。Android / 其他 iPhone 机型不做专项验证，但断点体系天然覆盖。

### 底色模糊的具体问题

四个页面都是「全屏固定层 + `filter: blur(25px)`」：

| 文件 | 定位 | 额外问题 |
|---|---|---|
| `views/WebHome.vue:380-390` | `fixed` + `100vw/100vh` | `background-attachment: fixed`（iOS 忽略且强制每帧重栅格） |
| `views/TagDetail.vue:1103-1114` | 同上 | 额外 `will-change: transform`（3M 设备像素常驻合成层） |
| `views/AlbumDetail.vue:2775-2784` | `absolute` + `height:100%` | 父级 `height:97vh` → 底部约 3vh **没有模糊层，露白条** |
| `views/AlbumPoolDetail.vue:336-345` | `absolute` + `height:100%` | 容器 `min-height:100vh` + body 8px margin → 同样露白边 |

DPR 3 下 393×852 = **1179×2556 ≈ 3.01M 设备像素**，`blur(25px)` 真实半径 = **75 设备像素** → 超出 iOS WebKit 单层滤镜预算，表现为：模糊不画（底色变清晰）/ 闪白 / 滚动时糊层与内容错位 / 掉帧。

### 顺手要修的两个既有主题色缺陷（移动端会放大）

1. **`AlbumBaseInfo.vue` 缺 `mainColorDarkDouble`**：`props` 只声明 `mainColor` / `mainColorDark`（:138-147），父组件也没传（`AlbumDetail.vue:37-39`），但 CSS 里 **15 处** `v-bind(mainColorDarkDouble)` → 全部 undefined → 文字/下划线颜色退化。手机单栏后这些元素占满整屏，问题比桌面显眼。
2. **`AlbumReviewEditor.vue` 主题色恒为 `transparent`**：`props` 只有 `album`（:131-137），而 `data()` 里定义 `mainColor/mainColorDark/mainColorDarkDouble = 'transparent'`（:141-143）→ 父组件传的 `:main-color*`（`AlbumDetail.vue:82-84`）落进 `$attrs` 被 `data` 覆盖 → 听后感页的箭头、日期底色、删除按钮**全是透明**。

## 已定决策

| 决策点 | 结论 |
|---|---|
| **子 Tab 形态** | 手机端改为**底部固定 TabBar**（BookRate `BottomTabBar` 同款）：6 项合并为一条，`flex:1` + `min-height:44px`，图标 + 12px 文字，底部补 `--safe-area-inset-bottom`；桌面保留左侧 200px 竖排侧栏 |
| 详情页顶部 | 手机端在页内保留一条 **48px sticky 返回条**（返回 + 专辑名 + 评分），**不引入全局 `MobileHeader`**（避免与用户选定的"仅底部 TabBar"方案冲突；全局移动壳留给后续版本） |
| **底色模糊** | **移动端降级为「缩略图 + 轻模糊」**：用 `/covers_thumb/` 的 300px JPEG（~十几 KB，`Cache-Control: immutable`）作底图，`blur(10px)`，**删掉** `background-attachment: fixed`，定位改 `inset: 0`；**桌面保持 `blur(25px)` 原样不变** |
| **范围** | 重点 = 专辑详情页 + 6 个子 Tab + 全局模糊底色；其他主页面 → P2；侧边栏弹窗中「比屏幕还宽」的几个（580/560/480px）在 P1 末尾收口，其余 P2 |
| **断点体系** | 沿用 BookRate 四档：`mobile <480` / `mobile-lg 480–767` / `tablet 768–1023` / `desktop ≥1024`；新增 `src/styles/breakpoints.css` 作为唯一来源，现有 7 处 `@media` 逐步归一 |
| **切换方式** | 结构变化（侧栏 → 底部 TabBar、哪些 DOM 渲染）用 **Vue 2 mixin 提供的 JS 断点**；纯样式用媒体查询。**追加式两层约定**：旧 `@media (max-width: 768px)` 保持不动，新触控层追加在后面（`max-width: 767px`），靠声明顺序取胜 |
| **验证方式** | Playwright **WebKit** 跑 iPhone 14 Pro 设备描述符（引擎最接近 Safari）+ 真机局域网抽查；`npx playwright install webkit`（~80MB，走 `127.0.0.1:7897` 代理） |
| 目标设备 | **仅 iPhone 14 Pro 自带 Safari**；不保证其他机型、不做 Android 专项 |
| 桌面回归红线 | 所有响应式规则只写在**新增的 `@media` 块**里；不改桌面既有声明值；**桌面截图基线**（P0 结束时存一份）作为回归依据 |
| 拖拽排序（iOS 不支持 HTML5 DnD） | 本版**不移植**触屏排序；`PlayerPlaylist` 手机端先降级为「不可拖拽 + 上移/下移按钮」兜底，手势排序留待后续版本 |

**为什么不用 BookRate 的 `composables/*.js`**：BookRate 是 Vue 3.4（`<script setup>` / `ref` / `onMounted`），MusicRate 是 Vue 2.6（实测 `node_modules/vue` = 2.7.16）。**只移植技术与 CSS，不移植代码**；JS 侧一律走 Options API + mixin。

### JS 断点 mixin（`src/mixins/mobile.js`，新增）

```js
export const BK = { MOBILE_MAX: 479, MOBILE_LG_MAX: 767, TABLET_MAX: 1023 }
export function computeBreakpoint(width) { /* 纯函数，便于单测 */ }
export default {
  data () { return { viewportWidth: 0, bp: 'desktop' } },
  computed: {
    isMobile ()     { return this.bp === 'mobile' },
    isMobileLg ()   { return this.bp === 'mobile' || this.bp === 'mobile-lg' }, // < 768，手机档统一口径
    isTablet ()     { return this.bp !== 'desktop' },
    isDesktop ()    { return this.bp === 'desktop' }
  },
  mounted () { this._applyWidth(); window.addEventListener('resize', this._applyWidth) },
  beforeDestroy () { window.removeEventListener('resize', this._applyWidth) } // ← Vue 2 名字
}
```

**口径统一**：本版所有"手机端"判断一律用 `isMobileLg`（`< 768px`），与 CSS 触控层 `@media (max-width: 767px)` **完全同源**，杜绝 JS 说手机、CSS 说桌面的错位。

### 触屏交互统一策略（详情页全量）

| 桌面写法 | 手机档替代 |
|---|---|
| `:hover` 才显示（音量条、☰ 菜单、歌词上传/AI 按钮、歌词时间戳、曲名跑马灯、标签删除 ×、AI 消息删除、听后感 tooltip） | `@media (hover: none)` 里 `opacity:1 !important` + 44px；或迁移为「点击弹出」面板 |

## 难点与对策

| # | 难点 | 对策 |
|---|---|---|
| D1 | **嵌套滚动**：`.main-content` 内滚 + 4 个子页各自的 `overflow-y:auto` + `position:sticky` 表头 | 手机档全部改为 `height:auto; overflow:visible`，**全页只有一层文档滚动**；sticky 表头改交给 `.md-topbar` |
| D2 | **`100vh` = large viewport**：iOS 工具栏可见时可视高只有 ~745-760px，固定栏底部被盖 | 背景层用 `inset:0` 避免 vh；可滚动容器用 `100dvh`（保留 `100vh` 作降级双写）；固定栏用 `padding-bottom: var(--safe-area-inset-bottom)` |
| D3 | **hover 依赖**：详情页 12 处功能只在 hover 出现，触屏 = 不可用 | `@media (hover: none)` 常显 + 44px；结构性功能（歌词操作组、音量、☰ 菜单）迁为「点击弹出」面板 |
| D4 | **鼠标专属评分**：单曲/歌词评分只有 `mousedown/mousemove/wheel`，全仓 `touchstart/touchmove` 仅 2 处（AppearancePanel） | 补 touch 事件（`passive:false` + `preventDefault` 防页面跟着滚）；再退化出一排快捷打分按钮兜底 |
| D5 | **模糊性能**：3M 设备像素 + 75px 真实模糊半径 | 底图换 300px 缩略图（栅格面积降到 ~1/10）+ `blur(10px)` + 去 `background-attachment:fixed`；`@supports not (filter: blur(1px))` 降级为 `mainColor` 渐变 |
| D6 | **`RhythmBall` 全屏固定动画层** + `@mousemove`：触屏无鼠标，且与模糊层叠加渲染 | 手机档 `display:none`（动画参数链路完全不动，桌面零回归）；如需手机端动画留待后续版本单独设计 |
| D7 | **拖拽排序 iOS 不支持 HTML5 DnD** | 本版不移植：`PlayerPlaylist` 手机端禁用 `draggable`，提供上移/下移按钮 |
| D8 | **`backdrop-filter` 68 处裸写** | 新增 `postcss.config.js` 定向 `overrideBrowserslist`（不动 `package.json.browserslist`）；同时清理 2 条 `-moz-backdrop-filter` 死声明 |
| D9 | **`--mask-opacity` 可为 0** → 背景 alpha=0 时 Safari 可能不建立 backdrop root，模糊整体消失 | `maskOpacity.js` 的 `MASK_MIN` 由 `0` 提到 `8`，并在 `@supports not` 降级块里把蒙版底色提到 0.85（否则文字读不清） |
| D10 | **主题色缺陷会被移动端放大**：`AlbumBaseInfo` 15 处 undefined、`AlbumReviewEditor` 恒 transparent | 作为 P0 前置修复（补 prop + 父组件绑定 + 删 `data` 里的 transparent 覆盖），否则断点做出来也是黑白错乱 |
| D11 | **Playwright WebKit ≠ 真 Safari** | 引擎同为 WebKit 已是最接近；device descriptor 必须挂在 `webkit` project 上（用 chromium 跑 iPhone 描述符会失真）；真机仍要抽查 8 项 |
| D12 | **真机连不上后端** | 已有现成方案：`portable/firewall_dev.ps1` 只放行回环 5000/8080，局域网调试需按脚本头注释临时放行；前端 `apiBase.js` 已按页面主机推导后端地址 |
| D13 | **桌面回归**：改 `AlbumDetail.vue` 极易碰坏桌面布局 | 红线 = 新规则只进 `@media (max-width: 767px)` 块，**不修改桌面声明值**；P0 结束存桌面截图基线，P1/P2 每阶段比对 |
