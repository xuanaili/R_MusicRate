# 对话 Token 消耗优化规则

> 从 BookRate 迁移（2026-08-10），适用于 MusicRate。通用规则，无项目特定引用。

## 核心原则
- 需求明确、改动范围小的任务，**直接改，不用规划**
- 单文件修改不需要 Plan Mode，不需要 Explore Agent
- 读取文件用 Grep 精准定位，避免全量读取大文件

## 判断标准

### 需要规划的场景（多文件、架构决策、需求不明确）
- 新增功能模块，涉及前后端多处改动
- 需要在多种方案间做选择
- 改动影响面大，需要用户确认方案

### 不需要规划的场景（需求明确、改动集中）
- 用户明确说了改哪个文件/组件
- 只改 1-2 个文件
- 改动模式清晰（如"接入主题"、"加跳转"）

## 具体优化规则

### 1. 减少重复读取
- 自己读文件和开 Agent 读文件**不要同时做**，二选一
- 单文件修改时，直接 Read 目标文件，不开 Agent
- 需要 Grep 的信息（如路由定义、API 响应结构），先用 Grep 定位再精准 Read

### 2. 精准读取
- 大文件（>500行）先 Grep 定位关键行，再 Read 指定范围
- 不要全量读取只是为了找一行代码（如 `AlbumDetail.vue` 约 92KB，务必先 Grep）

### 3. 避免过度探索
- 1 个 Agent 能完成的不开 2 个
- 探索范围聚焦在"要改的文件"和"直接依赖"
- 不需要理解整个系统才能改一个组件

### 4. 用户提示优化
- 如果用户在提示中说了"直接改，不用规划"，跳过 Plan Mode
- 如果用户指明了具体文件，跳过探索阶段
- 如果用户描述了改动模式（如"和其他组件风格统一"），直接按模式执行

## 参考案例
- 单文件改动却开了多个 Agent + Plan Mode + 全量读取大组件，token 消耗约为实际编码的 5-8 倍 → 避免
